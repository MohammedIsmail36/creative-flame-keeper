# تطوير شاشة الجرد (تسوية المخزون) إلى مستند جرد حقيقي

الهدف: تحويل التسوية من "إضافة سطر واختيار منتج" إلى مستند جرد يولّد النظام أصنافه تلقائيًا، والموظف يعدّ فقط، ثم مراجعة الفروق، ثم اعتماد التسوية. بدون فروع أو مخازن — المخزن واحد.

## دورة العمل الجديدة

```text
مسودة  →  جاري الجرد  →  مراجعة  →  معتمد
(رأس)     (عدّ فقط)     (الفروق)   (تسوية مخزنية + قيد)
```

### 1) رأس المستند (مسودة)
- تاريخ الجرد + المسؤول عن الجرد + وصف/ملاحظة.
- زر واحد: **بدء الجرد**.

### 2) بدء الجرد — توليد الأصناف تلقائيًا
عند الضغط، يأخذ النظام صورة لحظية (Snapshot) لكل الأصناف النشطة التي رصيدها أكبر من صفر، ويحفظ لكل صنف: الكمية في النظام لحظة البدء + التكلفة (متوسط الشراء). الحالة تصبح **جاري الجرد**، ولا يمكن إعادة التوليد بعدها.

### 3) شاشة العد — بسيطة ومغلقة
- كمية النظام **مخفية تمامًا** في هذه المرحلة (لا زر إظهار).
- الأعمدة: المنتج (الاسم • الماركة • الموديل + الكود) — الكمية المعدودة — الحالة.
- **مربع بحث سريع أعلى الشاشة** بنفس أسلوب فواتير الشراء: بحث بكود المنتج أو الموديل أو الماركة أو الاسم؛ عند اختيار المنتج ينتقل المؤشر مباشرة إلى خانة كميته ويظهر الصنف في أعلى القائمة، فلا يبحث المستخدم بعينه داخل الجدول.
- شريط تقدّم دائم: **تم جرد 10 من 12 — متبقي 2**.
- فرق أساسي: الخانة الفارغة = *لم يُجرد*؛ إدخال **0** = *تم الجرد والكمية الفعلية 0*.
- زر **+ إضافة صنف موجود فعليًا** لصنف غير موجود في القائمة (كميته في النظام تُسجّل صفرًا لحظة الإضافة).
- الحفظ تلقائي/يدوي لكل سطر بدون التأثير على المخزون.

### 4) مرحلة المراجعة
زر **إنهاء العد** ينقل المستند إلى **مراجعة**، وهنا فقط تظهر: كمية النظام عند بداية الجرد — الفعلي — الفرق — قيمة الفرق، مع ملخص (إجمالي فائض / إجمالي عجز / الصافي) والأصناف المتطابقة مطويّة.
- الرجوع إلى العد ممكن ما دام غير معتمد.
- بشأن الأصناف التي لم تُجرد: لا يُسمح بالاعتماد وهناك أصناف بلا كمية مُدخلة. يظهر تحذير بعددها مع زرّين: **الرجوع لإكمال العد**، أو **اعتبار المتبقي مطابقًا للنظام** (يُسجّل صراحةً أن كميتها الفعلية = كمية النظام، فلا تُنشئ فرقًا، ويُحفظ من قام بذلك).

### 5) الاعتماد
- تحذير إذا تغيّر رصيد أي صنف بين لحظة بدء الجرد ولحظة الاعتماد (بيع/شراء تم أثناء العد)، مع عرض الأصناف المتأثرة قبل المتابعة.
- الأصناف بفرق صفر لا تُنشئ حركة ولا تمنع الاعتماد (يُلغى الشرط الحالي الذي يمنع الاعتماد بسبب بنود بفرق صفر).
- يُنشئ حركة مخزون لكل صنف بفرق (بتكلفة متوسط الشراء) + قيد اليومية بالصافي كما هو حاليًا (5201 عجز / 4201 فائض مقابل 1104).
- الإلغاء يعمل كما هو اليوم (قيد عكسي + إعادة الكميات).

### 6) قائمة الجرد
أعمدة: رقم المستند — التاريخ — الحالة — عدد الأصناف / المجرودة — صافي الفرق قيمةً — رقم القيد. مع مرشّح بالحالة وشريط إحصاءات.

## التفاصيل التقنية

قاعدة البيانات (ميجريشن إضافي غير مُخرّب):
- `inventory_adjustments`: إضافة `counted_by uuid`، `counted_at timestamptz`، `reviewed_at timestamptz`، وتوسيع `status` ليشمل `counting` و`review` مع الإبقاء على `draft/posted/cancelled`.
- `inventory_adjustment_items`: جعل `actual_quantity` قابلًا لأن يكون NULL (غير مجرود) عبر عمود جديد `counted_quantity numeric NULL` بدل تغيير النوع، مع `is_extra boolean default false` للأصناف المضافة يدويًا، و`counted_at timestamptz`. يبقى `actual_quantity`/`difference` مُحتسبَين عند إنهاء العد للحفاظ على توافق التقارير الحالية.
- دالة `start_inventory_count(p_adjustment_id uuid)` تُنشئ سطور Snapshot لكل منتج نشط بكمية > 0 مع `system_quantity` و`unit_cost` من `get_avg_purchase_price`، وتضبط الحالة إلى `counting`. GRANT للـ authenticated و service_role.
- دالة `finish_inventory_count` لاحتساب `actual_quantity`/`difference`/`total_cost` من `counted_quantity` والانتقال إلى `review`.
