# خطة توسيع النشر الاجتماعي: فيسبوك وإنستجرام وتيك توك

## ملخص التوصية

نعم — يمكن تطبيق نفس فكرة نشر المنتجات على فيسبوك وإنستجرام وتيك توك، لكن كل منصة تختلف في متطلبات API والتعقيد. الأفضل هو تحويل الإعدادات الحالية من "تيليجرام فقط" إلى **بنية اجتماعية متعددة المنصات**، ثم تنفيذ المنصات تدريجياً بدءاً من **فيسبوك** (لأنه أساس إنستجرام أيضاً).

## الطريقة المقترحة

### 1. إعادة بناء الأساس الحالي

- تحويل جدول `telegram_settings` إلى جدول عام `social_publish_settings` يدعم عدة منصات:
  - `platform` (telegram | facebook | instagram | tiktok)
  - `credentials` (JSON مشفّر يحتوي التوكن/السري حسب المنصة)
  - `page_id` / `account_id`
  - `is_enabled`
  - `default_template_id`
- إنشاء جدول `social_post_templates` لقوالب النشر لكل منصة، مع متغيرات `{name}`، `{code}`، `{price}`، `{stock}`، إلخ.
- إنشاء جدول `social_scheduled_posts` لتخزين المنشورات المجدولة:
  - `product_id`، `platform`، `template_id`، `caption`، `media_urls`، `scheduled_at`، `status` (pending | published | failed)
  - `posted_url`، `external_post_id`، `error_message`
- إنشاء Edge Function موحّد `social-publish` يستقبل `platform` ويُنفّذ المنطق المناسب، مع Edge Function ثانٍ `social-scheduler` يعمل بـ cron لنشر المنشورات المجدولة.

### 2. المرحلة الأولى: فيسبوك (أساس لإنستجرام)

- ربط **Facebook Page** عبر Meta Graph API باستخدام Page Access Token.
- نشر منشور صور + نص على الصفحة.
- المتطلبات:
  - إنشاء تطبيق فيسبوك (Facebook App) أو استخدام معرّف تطبيق موجود.
  - صلاحية `pages_manage_posts`.
  - إضافة الحساب كمسؤول في الصفحة.
- تعقيد: متوسط — API مستقر وموثّق جيداً.

### 3. المرحلة الثانية: إنستجرام

- إنستجرام يُنشر عبر **Facebook Graph API** أيضاً، بشرط:
  - الحساب يكون Business/Creator.
  - الحساب مرتبط بـ Facebook Page.
  - صلاحيات `instagram_basic` و `instagram_content_publish`.
- نشر صورة واحدة أو مجموعة صور (Carousel) مع وصف.
- تعقيد: متوسط-مرتفع — يحتاج إعدادات إضافية للحساب التجاري، ودعم الفيديو/Reels أكثر تعقيداً.

### 4. المرحلة الثالثة: تيك توك

- تيك توك يدعم نشر **فيديو** أساساً، وليس صور ثابتة.
- الخيارات:
  - **TikTok Login Kit + Content Posting API**: يسمح بنشر فيديو من رابط URL أو رفع مباشر.
  - **TikTok for Business**: يحتاج موافقات وتكامل أعمق.
- نشر المنتج على تيك توك يتطلب إنشاء فيديو قصير (مثل صور المنتج متحركة) أو رابط فيديو موجود.
- تعقيد: مرتفع — API أقل مرونة، ويتطلب فيديو بدلاً من صور، وإعدادات OAuth أطول.

## تقدير التعقيد

| المنصة | التعقيد | المتطلبات الرئيسية | المدة التقريبية |
|--------|--------|-------------------|----------------|
| فيسبوك | متوسط | Facebook App + Page Admin Token | 1–2 أسابيع |
| إنستجرام | متوسط-مرتفع | Facebook Page + Business IG Account + Permissions | 2–3 أسابيع |
| تيك توك | مرتفع | TikTok Developer/Business App + OAuth + Video workflow | 3–4 أسابيع |
| إعادة البنية | متوسط | الجداول + Edge Functions + UI Settings | 1–2 أسابيع |

## المخاطر والقيود

- **فيسبوك/إنستجرام**: يجب مراجعة Meta للتطبيق إذا أردت استخدامه خارج بيئة التطوير (App Review). هذا قد يستغرق أياماً إلى أسابيع.
- **تيك توك**: لا يدعم نشر صور ثابتة بسهولة؛ يتطلب فيديو. كما أن API يختلف بين TikTok for Business و TikTok Developer.
- **التوكنات**: تحتاج إلى إعادة ربط/تحديث التوكنات دورياً، خاصةً OAuth tokens.
- **الجدولة**: تحتاج إلى Edge Function يعمل بـ cron (متاح في Supabase) أو إعداد Job Scheduler.

## الخطوات التالية المقترحة

1. الموافقة على إعادة بناء الأساس (مرحلة التحضير).
2. اختيار المنصة الأولى للتنفيذ (نوصي بـ **فيسبوك**).
3. تجهيز حسابات العمل على المنصة (Facebook Page + Business Manager + App).
4. تنفيذ الجداول والـ Edge Functions وشاشة الإعدادات الجديدة.
5. اختبار النشر على حساب تجريبي، ثم تكرار النمط لإنستجرام وتيك توك.

## المخرجات المتوقعة

- شاشة إعدادات اجتماعية موحّدة تضيف/تعدّل كل منصة.
- قوالب نشر مخصّصة لكل منصة.
- جدولة منشورات مستقبلية.
- سجل نشر موحّد يوضح الحالة (تم/فشل/معلّق) لكل منشور على كل منصة.
- زر النشر في صفحة المنتجات يتيح اختيار المنصة والقالب والنشر الفوري أو المجدول.
