## الهدف والضوابط

الهدف خفض مخاطر الاعتماديات تدريجياً دون تعريض الإنتاج لتحديثات كبرى غير مختبرة. قواعد التنفيذ:

- لا يُستخدم `npm audit fix --force`.
- كل دفعة مستقلة، وتنجح أولاً في TypeScript وجميع الاختبارات والبناء.
- تُنشر الدفعة على Staging وتُختبر وظيفياً قبل Farida، ثم تعتمد Farida قبل Alibea.
- لا تمس أي دفعة قواعد البيانات أو migrations أو Edge Functions ما لم تُذكر صراحة.
- تظل الأبنية الحالية على Farida وAlibea دون تغيير أثناء التحليل.

## تقييم النتائج المتبقية

### 1. React Router — خطر قابل للوصول ويحتاج أولوية

- الإصدار الحالي `6.30.4`، والمحاكاة ترفعه داخل النطاق إلى `6.30.6`، لكن تنبيهين في `react-router` يبقيان حتى الانتقال إلى `7.18.x`.
- التطبيق SPA ولا يستخدم SSR أو hydration خادمية، لذلك تنبيه constructor injection الخاص بـSSR غير قابل للمسار الحالي.
- يوجد مسار فعلي يحتاج تحصيناً: `src/pages/Auth.tsx` يأخذ `next` من query string، ويقبل حالياً أي قيمة تبدأ `/` ولا تبدأ `//`. القيمة التي تحتوي backslash مثل `/\evil.example` قد تتوافق مع سيناريو open redirect المذكور في التنبيه.
- العلاج الفوري ليس انتظار الترقية الكبرى: إضافة دالة مركزية تسمح بمسار داخلي same-origin فقط، وترفض backslash والبروتوكولات والمسارات المزدوجة والقيم غير الصالحة، مع اختبارات وحدات.

المراجع: `GHSA-wrjc-x8rr-h8h6` و`GHSA-337j-9hxr-rhxg` و`GHSA-jjmj-jmhj-qwj2`.

### 2. ExcelJS / UUID — نتيجة متوسطة غير مستغلة بالطريقة الحالية

- `exceljs@4.4.0` هو أحدث إصدار، ويعتمد `uuid@^8.3.0`؛ لا يوجد إصدار ExcelJS أحدث يصلح السلسلة حالياً.
- اقتراح npm بتخفيض ExcelJS إلى `3.4.0` غير مناسب ولا يُعتمد، لأنه تغيير رجوعي كبير ولا يمثل ترقية آمنة.
- تنبيه UUID يخص v3/v5/v6 عند تمرير Buffer. فحص ExcelJS المثبت وجد استدعاء `uuid.v4()` فقط ومن دون Buffer، ولم يجد المشروع استدعاءً مباشراً لـUUID؛ لذا لا يطابق الاستخدام الحالي مسار الاستغلال المعلن.
- يظل التنبيه مسجلاً حتى إصدار ExcelJS متوافق أو نجاح اختبار override إلى `uuid>=11.1.1` في بيئة معزولة، خصوصاً لاختبارات قراءة/كتابة وتصدير Excel.

المرجع: `GHSA-w5hq-g745-h8pq`.

### 3. Vite / esbuild — أدوات بناء وليست خدمة إنتاج

- `vite@5.4.21` يحتاج ترقية كبرى إلى `8.2.2` وفق التقرير، ومعه `@vitejs/plugin-react-swc` من 3 إلى 4 وفحص توافق Vitest.
- التنبيهات تخص خادم التطوير وقراءة ملفات أو طلبات من مواقع أخرى، وبعضها خاص بمسارات Windows. خادم Vite غير منشور؛ Nginx يقدم ملفات `dist` الثابتة.
- لا تُنفذ الترقية الكبرى مع الدفعة الآمنة؛ تُختبر مستقلة على نسخة نظيفة لأن أثرها يقع على البناء والاختبارات.

المراجع: `GHSA-4w7w-66w2-5vf9` و`GHSA-v6wh-96g9-6wx3` و`GHSA-fx2h-pf6j-xcff` و`GHSA-67mh-4wv8-2f99`.

### 4. Drizzle Kit / esbuild-kit — تطوير فقط

- `drizzle-kit@0.31.10` هو أحدث إصدار وما زال يعتمد `@esbuild-kit/esm-loader` الذي يجلب `esbuild@0.18.20`.
- الاستخدام المحلي محصور في `drizzle.config.ts`، ولا يوجد script لتشغيل Drizzle ضمن `package.json` ولا يدخل خادم الإنتاج.
- اقتراح npm بتخفيض Drizzle Kit إلى `0.18.1` مرفوض لأنه تغيير رجوعي كبير. يُراجع لاحقاً إمكان إزالة الأداة إن كانت غير مستخدمة فعلياً أو انتظار إصلاح upstream.

### 5. الإصلاحات داخل النطاق الحالي

- `brace-expansion`: DoS عبر توسع غير محدود؛ تحلها الإصدارات المرقعة في المحاكاة.
- `dompurify`: XSS؛ يأتي اختيارياً عبر jsPDF ويُرفع إلى `3.4.15` داخل النطاق الحالي.
- `nanoid`: loop عند generator مخصص بحجم صفر؛ يأتي عبر PostCSS ويُرفع إلى `3.3.18`.
- `js-yaml` و`yaml`: استهلاك CPU أو stack overflow عند YAML خبيث؛ استخدامهما هنا في أدوات lint/config، وتوجد ترقيات متوافقة.
