# النموذج المحاسبي للفروع — المرحلة 0 (وثيقة مرجعية)

> شركة قانونية واحدة، **دليل حسابات واحد**، والفرع **بُعد إلزامي على كل سطر قيد**.
> هذه الوثيقة هي المرجع المحاسبي الذي تُقاس عليه كل مرحلة تنفيذ لاحقة. لا تحتوي تفاصيل تنفيذ.

---

## 1. المبادئ الثابتة (Invariants)

| # | القاعدة |
|---|---|
| I1 | كل سطر قيد يحمل فرعاً **حقيقياً** يعبّر عن الواقع الاقتصادي، ولا يُغيَّر أبداً لأجل التوازن. |
| I2 | لكل قيد: **Σ مدين = Σ دائن لكل فرع** بعد إضافة سطور الموازنة. |
| I3 | حساب **تسوية بين الفروع (Branch Clearing)** رصيده **صفر على مستوى الشركة** في كل تاريخ، وسطوره **آلية فقط**. |
| I4 | حساب **مخزون بالطريق** رصيده = **المشحون غير المستلم** (ليس صفراً عند التجميع). |
| I5 | قيود الإقفال والافتتاح وترحيل الأرصدة **تحافظ على `branch_id` لكل سطر** — لا تُجمَّع فتفقد بُعد الفرع. |
| I6 | حركات المخزون **إضافية فقط** (كمية + قيمة)، وكل رصيد أو تقييم **قابل لإعادة البناء** منها بنفس النتيجة. |
| I7 | كل ترحيل **معاملة واحدة ذرّية**، ولا يُرحَّل مستند مرتين. |
| I8 | **WAC على مستوى (صنف × الفرع المالك)** موحَّد بين مخازن الفرع نفسه. |
| I9 | **فرع الحركة مشتق من المخزن** لا مُختار؛ ومخزن المستند تابع لفرع المستند. |
| I10 | **صفر الكمية = صفر القيمة**: أي كسر تقريب يُرحَّل صريحاً. |
| I11 | **لا مخزون سالب مُرحَّل**: المستند يُجهَّز كمسودة، والترحيل ينتظر توفر الكمية. |
| I12 | بعد الترحيل لا يتغير `branch_id` ولا `warehouse_id`؛ التصحيح بعكس وإعادة ترحيل. |

### الفرع بُعد داخلي وليس كياناً قانونياً
الشركة كيان قانوني وضريبي **واحد**: الإقرار الرسمي **مجمّع**، وتحليل الضرائب بالفرع **داخلي فقط**.
لو أصبح فرع كياناً قانونياً/ضريبياً مستقلاً مستقبلاً، فهذا **ليس Branch Accounting** ويستلزم إعادة تقييم نموذج الشركة.

سطور الضريبة تحمل فرع المستند؛ وفي المستند الموزع على عدة فروع تتبع الضريبة نفس أساس توزيع المصروف/الإيراد، بينما الإقرار الضريبي الرسمي يظل على مستوى الشركة.

### أكواد الحسابات Defaults لا Hard-coded
الأكواد أدناه **افتراضية**؛ المنطق يعتمد على **أدوار حسابات نظامية** (`branch_clearing_account_id`, `goods_in_transit_account_id`, …) لا على مقارنة الكود.

| الدور | الكود الافتراضي | الاسم |
|---|---|---|
| `cash` | 1101 | النقدية |
| `bank` | 1102 | البنك |
| `receivables` | 1103 | العملاء |
| `inventory` | 1104 | المخزون |
| `goods_in_transit` | **1106** | مخزون بالطريق |
| `branch_clearing` | **1107** | تسوية بين الفروع |
| `payables` | 2101 | الموردون |
| `revenue` | 4101 | الإيرادات |
| `inventory_gain` | 4201 | أرباح تسوية مخزون |
| `cogs` | 5101 | تكلفة المبيعات |
| `purchase_return_variance` | 5108 | فرق أسعار مرتجع مشتريات |
| `inventory_loss` | 5201 | عجز/تالف مخزون |

## 2. محرّك موازنة الفروع

بعد كتابة السطور الاقتصادية بفروعها الحقيقية:

1. لكل فرع: `net = Σ مدين − Σ دائن`.
2. لكل فرع `net ≠ 0`: يُنشأ **سطر واحد** على `branch_clearing` بعكس صافيه (`is_auto_balancing = true`).
3. مجموع سطور الموازنة = صفر دائماً ⇒ القيد متوازن للشركة ولكل فرع.

**مثال 3 فروع** (A = +100، B = −60، C = −40):

```text
Cr 1107   100   [A]
Dr 1107    60   [B]
Dr 1107    40   [C]
```

لا مطابقة زوجية A↔B، ولا حقل «الفرع المقابل» — فلا مديونية قانونية بين الفروع.

**تعدد الفروع في القيد مسموح فقط في**: تحويلات المخزون، الدفع/التحصيل المركزي، المصروفات الموزّعة، القيود اليدوية الخاصة.
فواتير البيع والشراء والمرتجعات **تبقى فرعاً واحداً**.

## 3. السيناريوهات الثمانية

الرموز: `HQ` = المركزي، `A`,`B` = فروع بيع. القيم توضيحية.

### 1) بيع نقدي داخل فرع A (بيع 1,000، تكلفة 600)

```text
Dr 1101 النقدية          1000  [A]
Cr 4101 الإيرادات        1000  [A]
Dr 5101 تكلفة المبيعات    600  [A]
Cr 1104 المخزون           600  [A]
```
فرع A متوازن ⇒ **لا سطور موازنة**. Branch Clearing = 0.

### 2) شراء آجل على المركزي (5,000)

```text
Dr 1104 المخزون          5000  [HQ]
Cr 2101 الموردون         5000  [HQ]
```
الكمية تدخل مخزن المركزي ⇒ مملوكة لـ HQ، وWAC(صنف × HQ) يُعاد حسابه.

### 3) سداد مورد فرع A من بنك الشركة (2,000)

```text
Dr 2101 الموردون         2000  [A]     ← الالتزام على فرع A
Cr 1102 البنك            2000  [HQ]    ← النقد خرج من بنك الشركة
--- المحرّك ---
Cr 1107 تسوية بين الفروع 2000  [A]
Dr 1107 تسوية بين الفروع 2000  [HQ]
```
A: 2000 مدين / 2000 دائن ✔ — HQ: 2000 مدين / 2000 دائن ✔ — 1107 للشركة = 0 ✔

### 4) شحن تحويل من HQ إلى A لم يُستلم (تكلفة 3,000 = `unit_cost_at_ship`)

```text
Dr 1106 مخزون بالطريق    3000  [HQ]
Cr 1104 المخزون          3000  [HQ]
```
فرع واحد ⇒ لا موازنة. **في نهاية اليوم: 1106 = 3,000 وليس صفراً** (مشحون غير مستلم).
قيمة مخزون الشركة لم تتغير (انتقلت بين حسابين).

### 5) استلام لاحق وجزئي في A (استلام 2,000 من 3,000)

```text
Dr 1104 المخزون          2000  [A]
Cr 1106 مخزون بالطريق    2000  [HQ]
--- المحرّك ---
Cr 1107                  2000  [A]
Dr 1107                  2000  [HQ]
```
الداخل بنفس `unit_cost_at_ship` ⇒ WAC(صنف × A) يُعاد حسابه، وWAC(صنف × HQ) لا يتأثر.
المتبقي 1,000 يبقى في 1106 [HQ] حتى استلام لاحق أو إغلاق صريح. 1107 = 0 للشركة ✔

### 6) مصروف مركزي 1,000 موزّع على A و B بالتساوي، مدفوع من بنك HQ

```text
Dr 52xx مصروف            500  [A]
Dr 52xx مصروف            500  [B]
Cr 1102 البنك           1000  [HQ]
--- المحرّك ---
Cr 1107                  500  [A]
Cr 1107                  500  [B]
Dr 1107                 1000  [HQ]
```
كل فرع متوازن، والمصروف ظهر في قائمة دخل كل فرع بنصيبه ✔

### 7) مرتجع تحويل — A يرفض 500 من المشحون

الرفض يحدد المشحون المتبقي كـ**مرتجع** فقط — لا قيد استلام في HQ، ويبقى رصيده في 1106 [HQ] طوال رجوعه فعلياً، ولا يظهر المخزون في HQ قبل وصوله. عند الاستلام الفعلي في HQ:

```text
Dr 1104 المخزون          500  [HQ]     ← عند الاستلام الفعلي فقط
Cr 1106 مخزون بالطريق    500  [HQ]
```

بنفس `unit_cost_at_ship` ⇒ لا ربح ولا خسارة، ولا موازنة (فرع واحد).
لو كان **فاقداً** بمسؤولية A: `Dr 5201 [A] / Cr 1106 [HQ]` + سطري موازنة بين A و HQ.

### 8) قيد إقفال السنة

أرباح كل فرع تُقفل **على نفس الفرع**:

```text
Dr 4101 الإيرادات      10000  [A]
Cr 5101 تكلفة المبيعات  6000  [A]
Cr 3102 أرباح محتجزة    4000  [A]
Dr 4101 الإيرادات       8000  [B]
Cr 5101 تكلفة المبيعات  5000  [B]
Cr 3102 أرباح محتجزة    3000  [B]
```
كل فرع متوازن ⇒ لا سطور موازنة. **بعد الإقفال تبقى أرصدة كل فرع قابلة للاستخراج** (I5).
أرصدة 1107 و1106 **لا تُقفل** إلى الأرباح المحتجزة: 1107 صفر أصلاً، و1106 أصل حقيقي مستمر.

## 4. معيار النجاح

| الفحص | النتيجة المطلوبة |
|---|---|
| توازن كل فرع | Σ مدين = Σ دائن لكل فرع في كل قيد |
| ميزانية الشركة | Σ الأصول = Σ الخصوم + حقوق الملكية |
| Branch Clearing | **صفر للشركة** في أي تاريخ |
| مخزون بالطريق | = المشحون غير المستلم |
| تقييم المخزون | قيمة مخزون المخازن لكل فرع = رصيد حساب المخزون 1104 لذلك الفرع |
| إجمالي مخزون الشركة | مجموع أرصدة 1104 لكل الفروع + رصيد مخزون بالطريق 1106 |
| قيمة مخزون الشركة | **لا تتغير** بالتحويل بين الفروع — المجموع (1104 + 1106) ثابت طوال فترة النقل، وليس فقط بعد الاستلام |

## 5. قواعد التكلفة (مرجع سريع)

| الحالة | الاتجاه | التكلفة | الفرق |
|---|---|---|---|
| مرتجع بيع مرتبط بفاتورة | داخل | **تكلفة البيع الأصلية** المحفوظة في حركة البيع | لا فرق تكلفة |
| مرتجع بيع بلا فاتورة | داخل | WAC الفرع الحالي | — |
| مرتجع شراء | خارج | WAC الفرع الحالي | الفرق مع إشعار المورد ⇒ `5108` على نفس الفرع |
| جرد زيادة | داخل | تسلسل إلزامي: WAC الفرع ← آخر تكلفة صحيحة للفرع ← آخر تكلفة شراء/تحويل موثوقة ← إن لم توجد أي تكلفة يطلب النظام تكلفة معتمدة **ولا يسمح بالترحيل بقيمة صفر** | `Dr مخزون / Cr 4201` |
| جرد نقص | خارج | WAC الفرع | `Dr 5201 / Cr مخزون` |
| تالف/فاقد | خارج | WAC الفرع أو `unit_cost_at_ship` إن كان بالطريق | `Dr 5201 [الفرع المتحمّل] / Cr مخزون أو 1106` |

**قاعدة عامة**: الخارج يخرج بتكلفة، والداخل يدخل بتكلفة، وأي فرق بين قيمة المستند المالي وقيمة المخزون يذهب إلى **حساب فرق صريح** — لا يُدفن في المخزون.
التكلفة المستخدمة تُحفَظ في الحركة فلا تتغير بتغير WAC لاحقاً.

---

## 6. النقل بين المخازن — نوعان

| النوع | الأثر |
|---|---|
| **داخل الفرع نفسه** | حركة **كمية فقط**: لا مخزون بالطريق، لا Branch Clearing، لا قيد محاسبي، ولا تغيير في WAC |
| **بين فرعين** | شحن ← استلام عبر 1106 بـ `unit_cost_at_ship` + سطور موازنة |

النوع يُحدَّد آلياً بمقارنة فرع مخزن المصدر بفرع مخزن الوجهة.

---

## 7. الصلاحيات

- الرؤية المحاسبية تُبنى على **فرع سطر القيد** لا على فرع المستند ⇒ مستخدم الفرع يرى جانبه من قيد بدأه المركزي دون تفاصيل المركزي المالية.
- مستند التحويل يراه المستخدم إذا كان فرعه **المُرسل أو المستقبل**.
